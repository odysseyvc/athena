Chapter 7

The owner's page, and agents that start a command

How the owner gets a page of controls that no other program and no other site can use: a one-time link in place of a password, four checks against the owner's own browser, captured text shown only as text, and one door for agents that call an address and agents that can only start a command.

After this chapter you should be able to
  • Give the owner of a local service a page of controls without giving every other program on the machine the same controls.
  • Sign a person in to a local page without a password.
  • Stop another site in the same browser from using the owner's session.
  • Show captured text on a page without letting it become part of the page.
  • Connect agents that can call an address, and agents that can only start a command, through one door.

7.1The problem: the only part that can change things

Everything an agent can reach in Athena is read-only (Chapter 6). The owner needs more than that: to pause, to let an agent in, to take a key away, to say yes to a waiting request, to forget the last ten minutes. A command line does all of this and almost nobody will use it. A page in the browser is what people expect, and it is also the first part of the system that can change something. If any program on the machine, or any web page open in the same browser, could reach it, the careful design of the reading side would be worth nothing.

7.2Signing in without a password

A password for a program on your own machine is one more secret to keep, and there is a better proof available: being able to read the data folder. Only programs running as the owner can.

Definition
One-time link
An address that signs its opener in once and then stops working. Here it carries a time and a signature made with a key that lives in the data folder; the server checks the signature, checks that the time is within two minutes, and remembers that the link has been used.

The icon near the clock and the command athena open both make such a link and hand it to the browser. The server answers with a session cookie and sends the browser on to the page, so the link itself is not left in the address bar. A client's token is not accepted here at all: the two doors share nothing.

def link(data, port, now=None):
    stamp = f"{int(now or time.time())}-{secrets.token_hex(6)}"
    return f"http://127.0.0.1:{port}/open?k={stamp}.{_sign(_secret(data), stamp)}"

7.3The owner's own browser is the threat

Once the cookie is set, the browser will send it to this address whenever anything asks it to. Two well-known attacks follow.

Definitions
Cross-site request forgery
A page on another site makes the owner's browser send a request to this one, and the browser attaches the owner's cookie to it.
DNS rebinding
A hostile site first answers from its own server and then points its own name at 127.0.0.1, so that its script, which the browser believes is still talking to the hostile site, is in fact talking to a program on this machine.

Four checks, each cheap, are made in a fixed order on every request to the page's interface:

  1. Is it this address? The Host header must be this machine's own address and port. A rebinding site arrives under its own name and is refused.
  2. Is it the owner? The session cookie must be one this run of the program issued.
  3. Is it their own click? A change must be a POST carrying a header that a page on another site cannot add without the browser asking this server first, and this server never says yes.
  4. Does the browser agree? If the browser states where the request came from, it must be this address.

The cookie is also marked so that the browser does not send it with requests started by other sites. Any one of these would stop the common attack; they are all there because each fails differently. All of them, and the protocol address's own refusal of a foreign origin (which the current protocol specification requires), are covered by tests. Verified

7.4Showing other people's text

The page shows window titles and screen text, which were written by strangers (Chapter 4). On a web page that is a second version of the same problem: text that contains markup can become script. Two rules deal with it. The page is three fixed files, and a content security policy tells the browser to run no script and apply no style but those files. And the script never builds markup from data: every captured string reaches the page as a text node. A test reads the script and fails if it ever uses one of the calls that would break that rule.

What the owner sees comes through the same function an agent's request goes through, as a client called owner. So the owner sees the same marks an agent would: quoted text is shown as a quotation, a withheld piece is shown as withheld, and the owner's own looking is a line in the log.

7.5What the page does

Table 7.1. The sections of the page.
SectionWhat it is for
NowThe last hour as an agent would be given it.
ApprovalsEach waiting request with its exact inputs, and two buttons.
AgentsWho has a key, what it opens, what each last asked for; make a key, take one away.
About youThe owner's own notes, editable; a model's statements with their evidence and a button reading "This is wrong".
Search, DaysThe same search and day summary agents get.
PrivacyForget the last minutes; add to the never-record list; where the folder is and what the last run cost.
LogEvery request, allowed or refused.

"This is wrong" matters more than it looks. A model of a person that the person cannot correct will drift, and nothing in the evidence can show it. A statement the owner rejects is retired with its dates and the reason, like one the evidence stopped supporting, and it is no longer served as holding.

The icon near the clock is deliberately small: whether recording is on, pause for half an hour, two hours or until resumed, and a notice when a request starts waiting. The notice names the client and nothing from the request, because a request's inputs are chosen by the agent and a notification is not a place to show them.

7.6Agents that cannot call an address

Most coding agents can be given an address on the same machine and a header to send. Some desktop assistants cannot: they reach remote servers from their maker's cloud, which cannot see this machine at all, and locally they can only start a command and speak the protocol over its input and output. Verified from the vendors' documentation, November 2026.

The answer is a second way in that is not a second door. athena stdio is a command an assistant can start. It holds no data and decides nothing. Each call it receives is passed to the server on this machine with that client's own key, taken from the environment, which is what the protocol asks of a local server. Scopes, approvals and the log are therefore the same on both routes, and there is still one function through which everything served must pass.

def run(tool, **args):
    r = httpx.post(url, headers={"Authorization": f"Bearer {token}", ...},
                   json={"jsonrpc": "2.0", "id": 1, "method": "tools/call",
                         "params": {"name": tool, "arguments": args}})
    if r.status_code == 401:
        return json.dumps({"error": "Athena does not accept this client's key. ..."})
    return r.json()["result"]["content"][0]["text"]

What each kind of agent must be given, an address and a header or a command and a variable, is a table of data in one file, taken from each vendor's own page. The page and the command athena connect print the exact lines. Athena does not write into another program's settings.

What went wrong, and what is not known

The routes were tested with the protocol's own client library over both transports, and one assistant reads over HTTP through its own connection code. No other vendor's agent has been connected for real: the shapes in the table are read from documentation, not observed. Unverified

The first figure the page showed for cost was "1548% of one processor core", true of the two seconds after start in which libraries load, and worthless. A cost is now shown only after six minutes of running.

Summary
  • The page that can change things has its own door: a one-time link signed with a key in the data folder.
  • Host, session, an unforgeable header and the browser's stated origin are checked, in that order, on every request.
  • Captured text reaches the page only as text, under a policy that runs nothing but three fixed files.
  • The owner sees what an agent would, with the same marks, and can call a model's statement wrong.
  • An agent that can only start a command is given a pass-through, not a second copy of the door.
Exercises
  1. The one-time link is valid for two minutes. What could another program running as the owner do in that time? Does shortening it help?
  2. Which of the four checks stops DNS rebinding, and why does the cookie's same-site mark not?
  3. The notification names the client but not the request. Give an input an agent could choose that would make a notification dangerous to show.
  4. Extend the design: an owner wants to approve from their phone. What has to change about the door, and what must not?
