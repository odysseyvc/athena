The book

A model of a person, kept on their own machine.

A short textbook for the technically minded on how to learn what someone is working on from their own computer, keep it in files they control, and serve it to their agents without letting the words of strangers become instructions. Every mechanism is explained from the idea down to the code that runs.

What kind of book this is. It describes a real system that runs on one person's Windows machine and is still being built. Every claim about what was run is graded by how it is known, and anything not yet run is marked as such. The grades are explained in How to read the evidence. Read that page first; it takes three minutes.

How to read it

The chapters are organised by idea, not by the order in which things were built. Each one states what you will be able to do, defines its terms before using them, shows the design and the reasons for it, walks through the code that runs, says what went wrong in practice, and ends with exercises. Chapters refer to each other by number.

To understand the idea

Read Part I, then Chapter 4. That is the smallest complete picture.

To build one

Read straight through with the code open. Several exercises ask you to change it.

To judge whether to trust one

Read Part II in full, then Chapter 7 and Chapter 8.

Contents

Part I · Foundations

What a model of a person is, what already exists, and what a computer will say about its owner.

  1. 1What a portable user model is

    Why an agent that only remembers what it is told knows little about you, what a user model adds, what the products that exist do and do not offer, and how to decide which parts to buy and which to build.

  2. 2Capture: what a computer will tell you about its owner

    Six signals Windows gives without a screenshot or a keyboard hook, ordered by what each costs, how the text a person typed is told from the text that was already there, and when to fall back on reading a picture.

Part II · Safety

What must never be recorded, and how other people's words are kept from becoming instructions or facts.

  1. 3Privacy rules held by code

    Why a rule that matters cannot be a request to a model, the order of checks that lets an excluded window leave no trace, how secrets are removed before anything is written, and how deleting stays deleted when there is a search index.

  2. 4Whose words are whose

    Most of a screen was written by other people. How to separate what a person did, what they wrote and what they merely saw, mark every served item with where it came from, and what a list of patterns and a classifier each catch of text written to steer an agent.

Part III · Use

Finding things again, a memory that is kept up, and letting agents in by the right door.

  1. 5Search, and a memory that is kept up

    Why matching words fails when people ask in their own words, how words and meaning are joined into one ranking on a laptop, what a reranker did here, and how a model keeps a memory by adding, confirming, revising and retiring statements that code checks.

  2. 6Serving: keys, rooms and a log

    How a local service lets agents read without letting them roam: a token per client, scopes as rooms, approval one request at a time, tools an agent can run unasked, and a record of everything that was given.

Part IV · Knowing it works

Measuring quality and cost together, and an honest account of what exists.

  1. 7Measuring it

    How to score a system that watches a private life without using that life as test data, why a rule scored on the cases it was tuned on flatters itself, and how cost decides between two options that score alike.

  2. 8What is built

    Every part of the system with its present state: what runs every day, what has run once, what is written and never run, and what does not exist.

Every factual claim on this site carries an evidence grade, and anything not yet run is marked as such.
